# Lab 00 - 90分で学ぶ Azure の基礎

## このハンズオンについて

このハンズオンは、Azure をはじめて触る方が **約 90 分** で Azure の主要サービスを一通り体験するための入門ラボです。AZ-104 の各ラボ（各 50 分）を短縮・再構成し、クラウド管理者に必須の「4 本柱」を 1 つのシナリオでつなげて学びます。

- **リソースの整理** … リソース グループとタグ
- **ネットワーク** … 仮想ネットワーク（VNet）とサブネット、ネットワーク セキュリティ グループ（NSG）
- **コンピューティング** … 仮想マシン（Linux Web サーバー）
- **ストレージ** … ストレージ アカウントと Blob コンテナー

最後に作成したリソースをまとめて削除し、**課金を止めるところまで** を確実に体験します。

> **必要なもの**: 有効な Azure サブスクリプション（無料アカウントでも可）。手順は **East US** リージョンを前提に記載していますが、任意のリージョンに変更できます。サブスクリプションの種類によっては一部の機能や SKU の可用性が異なる場合があります。

## 所要時間の目安: 90 分

| ステップ | 内容 | 目安時間 |
| --- | --- | --- |
| Task 1 | リソース グループとタグを作成する | 約 10 分 |
| Task 2 | 仮想ネットワーク（VNet）とサブネットを作成する | 約 15 分 |
| Task 3 | 仮想マシン（Web サーバー）を作成する | 約 20 分 |
| Task 4 | NSG でポートを開き Web ページを公開する | 約 13 分 |
| Task 5 | ストレージ アカウントと Blob を作成する | 約 15 分 |
| Task 6 | リソースをまとめて削除する（重要） | 約 12 分 |

## シナリオ

あなたは新しくクラウド管理者になりました。まずは検証用のネットワークを設計し、その中に Web サーバーとファイル保管用のストレージを Azure 上に用意し、動作を確認してから安全に片付ける、という一連の作業を通じて Azure の基本操作を身につけます。

## 身につくスキル

+ Task 1: リソース グループを作成し、タグで整理する
+ Task 2: 仮想ネットワーク（VNet）とサブネットを作成する
+ Task 3: 仮想マシン（Linux + NGINX）を作成し、作成した VNet に配置する
+ Task 4: NSG のインバウンド規則を追加し、Web ページをブラウザーで確認する
+ Task 5: ストレージ アカウントと Blob コンテナーを作成し、ファイルをアップロードする
+ Task 6: リソース グループを削除して、すべてのリソースと課金を停止する

## Task 1: リソース グループとタグを作成する

Azure のすべてのリソースは **リソース グループ** という「入れ物」に入ります。まずこの入れ物を作り、後片付けを簡単にします。

1. **Azure ポータル** にサインインします - `https://portal.azure.com`

1. ポータル上部の検索ボックスで `リソース グループ`（または `Resource groups`）を検索し、選択します。

1. **＋ 作成** を選択します。

1. **基本** タブで、次の値を指定します。

    | 設定 | 値 |
    | --- | --- |
    | サブスクリプション | お使いの Azure サブスクリプション |
    | リソース グループ | `rg-az104-userNN` |
    | リージョン | **(US) East US** |

    > **Note:** `NN` は自分の受講者番号（`01`〜`10`）に置き換えてください。例: 3 番目の受講者なら `rg-az104-user03`。複数名で同じサブスクリプションを共有してもリソース グループが分かれるため、互いのリソースが混ざりません。以降のタスクでも同じリソース グループ名を使用します。

1. **タグ** タブに移動し、次のタグを追加します。タグはコスト管理やリソースの整理に使う「ラベル」です。

    | 名前 | 値 |
    | --- | --- |
    | `env` | `handson` |
    | `owner` | あなたの名前やメールなど |

1. **確認および作成** → **作成** を選択します。

1. 作成が完了したら、通知から **リソース グループに移動** を選択し、**概要** ページでタグが設定されていることを確認します。

    > **ポイント**: リソース グループ単位でまとめて削除できるため、ハンズオンや検証では「専用のリソース グループ」を作るのが後片付けのコツです。

## Task 2: 仮想ネットワーク（VNet）とサブネットを作成する

**仮想ネットワーク（VNet）** は、Azure 上に作る「あなた専用のプライベート ネットワーク」です。VM などのリソースは VNet の中の **サブネット** に配置され、互いに通信できます。ここでは次の Task で作る VM を入れるための VNet とサブネットを先に用意します。

1. ポータルの検索ボックスで `仮想ネットワーク`（または `Virtual networks`）を検索して選択し、**＋ 作成** を選択します。

1. **基本** タブで、次の値を指定します。

    | 設定 | 値 |
    | --- | --- |
    | リソース グループ | **rg-az104-userNN**（Task 1 で作成したもの） |
    | 仮想ネットワーク名 | `vnet-az104-userNN` |
    | リージョン | **(US) East US** |

1. **セキュリティ** タブに移動します。ここでは VNet に追加できるセキュリティ機能をまとめて確認できます。**このハンズオンではすべて無効（既定値）のまま** にして先に進みますが、それぞれの役割を理解しておきましょう。

    | セキュリティ機能 | 役割 | このラボでの設定 |
    | --- | --- | --- |
    | 仮想ネットワークの暗号化 | VNet 内を流れるトラフィックを自動で暗号化します（対応 VM・高速ネットワークが必要）。 | 無効（オフのまま） |
    | Azure Bastion | パブリック IP なしで、ブラウザーから VM に安全に RDP/SSH 接続できるマネージド サービス（有料）。 | 無効（オフのまま） |
    | Azure Firewall | VNet を保護するクラウドベースのマネージド ファイアウォール。送受信トラフィックを一元的に制御します（有料）。 | 無効（オフのまま） |
    | Azure DDoS ネットワーク保護 | DDoS 攻撃から VNet 内のリソースを守る高度な保護サービス（有料）。 | 無効（オフのまま） |

    > **ポイント**: これらは「後からでも有効化できる」追加のセキュリティ層です。実運用では、VM への安全な接続に **Azure Bastion**、通信の集中制御に **Azure Firewall**、公開サービスの保護に **DDoS 保護** を検討します。いずれも課金が発生するため、検証環境では既定の無効のままにしておくのが安全です。なお、サブネット単位の通信制御は Task 4 で扱う **ネットワーク セキュリティ グループ（NSG）** で行います（NSG は無料で使えます）。

1. **アドレス空間** タブに移動します。**IPv4 アドレス空間** が `10.0.0.0/16` になっていることを確認します（既定値のままで構いません）。

1. 既定のサブネット（`default`）を選択し、名前を `subnet-web`、サブネット アドレス範囲を `10.0.1.0/24` に設定します。

    > **ポイント**: `/16` の VNet には約 65,000 個、`/24` のサブネットには約 250 個の IP アドレスが含まれます。各サブネットでは Azure が 5 つの IP アドレスを予約します。

1. **確認および作成** → **作成** を選択します。

1. デプロイ完了後、**リソースに移動** を選択し、**サブネット** ページで `subnet-web` が作成されていることを確認します。

---

## Task 3: 仮想マシン（Web サーバー）を作成する

Azure で最も基本的なコンピューティング リソースである **仮想マシン（VM）** を作成します。ここでは Ubuntu Linux を使い、Task 2 で作成した VNet に配置して、後のタスクで Web サーバーとして公開します。

1. ポータルの検索ボックスで `仮想マシン`（または `Virtual machines`）を検索して選択し、**＋ 作成** → **Azure 仮想マシン** を選択します。

1. **基本** タブで、次の値を指定します（記載のないものは既定値のままにします）。

    | 設定 | 値 |
    | --- | --- |
    | リソース グループ | **rg-az104-userNN**（Task 1 で作成したもの） |
    | 仮想マシン名 | `vm-web-az104-userNN` |
    | リージョン | **(US) East US** |
    | 可用性オプション | インフラストラクチャ冗長は必要ありません |
    | セキュリティの種類 | **トラステッド起動の仮想マシン**（既定のまま） |
    | イメージ | **Ubuntu Server 24.04 LTS**（表示があるバージョンで可） |
    | VM アーキテクチャ | **x64** |
    | サイズ | `Standard_D2als_v7`（小さめで十分です） |
    | 認証の種類 | **パスワード** |
    | ユーザー名 | `azureuser` |
    | パスワード | 12 文字以上の任意の強力なパスワード（メモしておく） |

    > **Note**: SKU が利用できない、またはクォータ超過で失敗する場合は、サイズや **リージョン** を変更してください。

1. 同じ **基本** タブの **受信ポートの規則** で、**パブリック受信ポート** は **選択したポートを許可する** を選び、**SSH (22)** を選択します。

    > **Note**: 学習環境のため SSH を公開しています。本番環境では **Azure Bastion** や **Just-in-Time アクセス** の利用を検討してください。

1. **ディスク** タブに移動します。**OS ディスクの種類** で **Standard SSD** を選択します（**VM と共に削除** はオンのまま）。

1. **ネットワーク** タブに移動し、Task 2 で作成したネットワークを指定します（記載のないものは既定値のままにします）。

    | 設定 | 値 |
    | --- | --- |
    | 仮想ネットワーク | **vnet-az104-userNN** |
    | サブネット | **subnet-web (10.0.1.0/24)** |
    | パブリック IP | 既定値（新規作成）のまま |
    | NIC ネットワーク セキュリティ グループ | **基本** |
    | パブリック受信ポート | **選択したポートを許可する** |
    | 受信ポートの選択 | **SSH (22)** |
    | VM が削除されたときにパブリック IP と NIC を削除する | オフ（既定のまま） |
    | 高速ネットワークを有効にする | 既定のまま（このサイズでは自動でオン／グレーアウト） |
    | 負荷分散のオプション | **なし** |

    > **ポイント**: 仮想ネットワークに **vnet-az104-userNN** が自動で選ばれない場合は、リージョンが VNet と同じ **East US** になっているか確認してください。VNet と VM のリージョンは一致している必要があります。

1. 他のタブは既定値のまま進めます。**確認および作成** → **作成** を選択します。

1. デプロイには数分かかります。完了したら **リソースに移動** を選択します。

1. **概要** ページで **パブリック IP アドレス** をメモします（Task 4 で使用します）。

### VM に接続して Web サーバー（NGINX）を導入する

ここでは追加ツール不要でブラウザーから使える **Cloud Shell** を利用します。

1. ポータル上部のツールバーで **Cloud Shell** アイコン（`>_`）を選択します。初回は **Bash** を選びます。**作業の開始** 画面では **ストレージ アカウントは不要です** を選び、**サブスクリプション** を選択して **適用** します（このラボでは SSH コマンドを実行するだけなので、ストレージのマウントは不要です）。

1. Cloud Shell で次のコマンドを実行し、VM に SSH 接続します（`<パブリックIP>` は先ほどメモした値に置き換えます）。

    ```bash
    ssh azureuser@<パブリックIP>
    ```

    初回接続時のフィンガープリント確認では `yes` を入力し、続けて設定したパスワードを入力します。

1. VM に接続できたら、次のコマンドで NGINX Web サーバーをインストールします。

    ```bash
    sudo apt-get update && sudo apt-get install -y nginx
    ```

1. トップページを分かりやすい内容に書き換えます。

    ```bash
    echo "<h1>Hello Azure! This is vm-web-az104-userNN</h1>" | sudo tee /var/www/html/index.html
    ```

1. `exit` と入力して SSH 接続を終了します。

    > この時点ではまだブラウザーから見えません。次の Task で **NSG のポート 80 を開放** します。

## Task 4: NSG でポートを開き Web ページを公開する

**ネットワーク セキュリティ グループ（NSG）** は、リソースへの通信を許可・拒否するファイアウォールのようなものです。HTTP（ポート 80）を許可して Web ページを公開します。

1. **vm-web-az104-userNN** の画面左メニューで、**ネットワーク** → **ネットワークの設定**（または **ネットワーク設定**）を選択します。

1. **ポートのルールの作成** → **受信ポートのルール** を選択します。

1. **受信セキュリティ規則の追加** ウィンドウで、次の値を指定します（記載のないものは既定値のまま）。

    | 設定 | 値 |
    | --- | --- |
    | ソース | **Any** |
    | ソース ポート範囲 | `*` |
    | 宛先 | **Any** |
    | サービス | **Custom** |
    | 宛先ポート範囲 | `80` |
    | プロトコル | **TCP** |
    | アクション | **許可** |
    | 優先度 | `310` |
    | 名前 | `Allow-HTTP` |

1. **追加** を選択し、ルールが一覧に表示されることを確認します。

1. 新しいブラウザー タブを開き、`http://<パブリックIP>` にアクセスします。

1. **Hello Azure! This is vm-web-az104-userNN** と表示されれば成功です。

    > **ポイント**: 表示されない場合は、(1) NGINX が起動しているか（`systemctl status nginx`）、(2) NSG のポート 80 が **許可** になっているか、(3) URL が `https` ではなく `http` か、を確認します。

## Task 5: ストレージ アカウントと Blob を作成する

Azure でファイルやデータを保存する基本サービスが **ストレージ アカウント** です。ここに **Blob コンテナー** を作り、ファイルをアップロードします。

1. ポータルの検索ボックスで `ストレージ アカウント`（または `Storage accounts`）を検索して選択し、**＋ 作成** を選択します。

1. **基本** タブで、次の値を指定します（記載のないものは既定値のまま）。

    | 設定 | 値 |
    | --- | --- |
    | サブスクリプション | 自分のサブスクリプション |
    | リソース グループ | **rg-az104-userNN**（Task 1 で作成したもの） |
    | ストレージ アカウント名 | 3〜24 文字の英小文字と数字で、グローバルに一意な名前（例: `staz104userNN`） |
    | リージョン | **(US) East US** |
    | 優先ストレージの種類 | **Azure Blob Storage または Azure Data Lake Storage** |
    | パフォーマンス | **Standard**（ほとんどのシナリオに対して推奨される 汎用 v2 アカウント） |
    | 冗長性 | **ローカル冗長ストレージ (LRS)**（学習用のため安価な LRS を選択） |

1. **レビューと作成** を選択し、検証の完了後に **作成** を選択します。デプロイ完了後、**リソースに移動** を選択します。

1. 左メニューで **データ ストレージ** → **コンテナー** を選択し、**＋ コンテナー** を選択します。

1. 名前に `handson-files` と入力し、**作成** を選択します。

    > **Note**: 既定ではコンテナーは非公開（匿名アクセス不可）です。これは安全な既定値です。

1. 作成した **handson-files** コンテナーを開き、**アップロード** を選択します。

    > **トラブルシューティング**: コンテナーを開いたときに **「このリクエストは、この操作を実行する承認がありません」（エラー コード 403）** と表示される場合は、ストレージ アカウントの **ファイアウォール（ネットワーク アクセス制限）** でアクセスがブロックされています。次の手順で解除します。
    >
    > 1. ストレージ アカウントの左メニューで **セキュリティとネットワーク** → **ネットワーク** を選択します。
    > 1. **パブリック ネットワーク アクセス** で **すべてのネットワークから有効** を選択します（または **選択した仮想ネットワークと IP アドレスから有効** のまま、**ファイアウォール** の **クライアント IP アドレスを追加する** を選択して自分の IP を許可します）。
    > 1. **保存** を選択し、数分待ってからコンテナーを開き直します。
    >
    > **Note（Azure Policy でパブリック アクセスが無効な環境）**: 組織の **Azure Policy** によって **パブリック ネットワーク アクセス = 無効（Disabled）** が強制され、自分の権限で変更できない場合は、上記の手順でも有効化できません。この場合は **コンテナー作成まで（前の手順まで）で完了として構いません**。以降のアップロード手順は任意です。どうしても実施したい場合は、管理者に Policy の除外（例外）を依頼するか、ストレージにプライベート エンドポイントを構成して Task 3 の VM 内から実施してください。

1. （任意）任意のファイル（テキスト ファイルや画像など、何でも構いません）を選び、**アップロード** を選択します。

1. アップロードした Blob が一覧に表示されることを確認します。Blob を選択すると、サイズ・アクセス層・URL などのプロパティを確認できます。

    > **ポイント**: **アクセス層（ホット / クール / コールド / アーカイブ）** を切り替えると、アクセス頻度に応じてストレージ コストを最適化できます。

## Task 6: リソースをまとめて削除する（重要）

Azure では、リソースが存在する限り課金が発生する場合があります。ハンズオンの最後は **必ずクリーンアップ** を行い、余計な費用が発生しないようにします。Task 1 で専用のリソース グループを作ったので、それを削除するだけで VNet・VM・NSG・ストレージがすべて消えます。

1. ポータルの検索ボックスで `リソース グループ` を検索し、**rg-az104-userNN**（自分のリソース グループ）を開きます。

1. 上部メニューで **リソース グループの削除** を選択します。

1. 確認画面で、削除されるリソース（仮想ネットワーク、VM、ディスク、パブリック IP、NSG、ストレージ アカウントなど）が含まれていることを確認します。

1. 指示に従ってリソース グループ名 `rg-az104-userNN`（自分のリソース グループ名）を入力し、**削除** を選択します。

1. 数分後、リソース グループの一覧から **rg-az104-userNN** が消えていることを確認します。

    > **ポイント**: リソース グループを削除すると、その中のすべてのリソースが削除されます。残したいリソースがある場合は、削除前に別のリソース グループへ移動しておきます。

## まとめ

このハンズオンでは、Azure の基礎を約 90 分で一巡しました。

- **リソース グループ / タグ** … リソースを整理し、まとめて管理・削除する方法を学びました。
- **仮想ネットワーク（VNet）** … VNet とサブネットを設計し、リソースを配置する土台を作りました。
- **仮想マシン** … Linux VM を VNet 上に作成し、Web サーバーを構築しました。
- **ネットワーク（NSG）** … ポートを開放して通信を許可・制御する方法を学びました。
- **ストレージ** … Blob コンテナーにファイルを保存する方法を学びました。
- **クリーンアップ** … リソースを削除して課金を止める、運用で最も重要な習慣を身につけました。
